# ⚡ FEATURES — Meilleur de MAL + Letterboxd + Innovations
> Sans IA intégrée · Manhwa-first · Tout ce qui compte vraiment

---

## 📐 Méthodologie

On a analysé les meilleures features de :
- **MyAnimeList (MAL)** — tracking, stats, communauté massive
- **Letterboxd** — design, reviews, social, listes
- **AniList** — UX moderne, graphiques, tags communautaires

Pour chaque feature : on prend le meilleur, on supprime le superflu, et on réinvente pour le manhwa spécifiquement.

---

## 📚 CATÉGORIE 1 — BIBLIOTHÈQUE & TRACKING

### ✅ Feature 1.1 — Les 5 statuts de lecture (inspiré MAL)
**Ce que fait MAL :** Reading / Completed / On-Hold / Dropped / Plan to Read
**Ce qu'on améliore :**
- Renommer pour le manhwa : 📖 En cours / ✅ Terminé / ⏸ En pause / ❌ Abandonné / 📋 À lire
- Ajouter un **6ème statut : 🔄 Relecturé** (Letterboxd l'a pour les films — très utilisé)
- Rajouter sur chaque entrée : **le chapitre actuel** (pas juste le statut)
- Rajouter : **date de début** et **date de fin** (pour les stats historiques)
- Rajouter : **note de relecture** (différente de la note originale — évolution du goût)

**Innovation :** Timeline visuelle de lecture sur le profil (heatmap style GitHub — voir quand tu as lu quoi).

---

### ✅ Feature 1.2 — Notes enrichies (inspiré Letterboxd)
**Ce que fait Letterboxd :** note /5 + review courte en option
**Ce qu'on améliore :**
- Note /10 via slider + cristal animé (voir Product Design)
- **Note publique** ET **note privée** séparées (ta vraie opinion vs ce que tu montres)
- **"Coup de cœur"** : marquer un manhwa comme coup de cœur personnel (en plus de la note) — icône ♥ spéciale sur le profil
- **Tags personnels privés** : taguer ses propres titres (#à-recommander, #guilty-pleasure, #dropped-twice)

---

### ✅ Feature 1.3 — Progression par chapitre (MAL mais bien fait)
**Ce que fait MAL :** juste un nombre de chapitres lus
**Ce qu'on améliore :**
- Barre de progression visuelle sur chaque carte
- **Mise à jour rapide** : bouton "+1 chapitre" accessible sans ouvrir la fiche
- **Objectif de lecture** : "Je veux finir ce manhwa avant le 15 mars" → reminder
- **Streak de lecture** : X jours consécutifs avec au moins 1 chapitre lu → badge

---

### 🚀 Feature 1.4 — INNOVATION : Import multi-plateformes
**Ce qui n'existe nulle part bien :**
Importer sa bibliothèque depuis MAL, AniList, ou un CSV en un clic.
Mapping automatique des titres + statuts + notes.
**Pourquoi révolutionnaire :** Les gens n'abandonnent pas leur plateforme actuelle à cause de la friction de re-saisir 200 titres. Lever cette barrière = conversion massive.

---

### 🚀 Feature 1.5 — INNOVATION : "Reading Journal" privé
Pas juste une note — un journal de bord par titre.
Pour chaque manhwa, l'utilisateur peut ajouter des **notes privées** liées à un chapitre spécifique :
- "Chapitre 45 — cette scène m'a fait pleurer"
- "Arc 3 — baisse de qualité visible"
- "Relu en décembre 2025 — encore meilleur qu'en 2023"

Ces notes sont 100% privées, jamais indexées, jamais montrées. C'est un journal intime de lecteur. Ça crée une rétention extraordinaire car les gens ne quittent jamais un endroit où leur vécu personnel est stocké.

## ⭐ CATÉGORIE 2 — REVIEWS & NOTATION

### ✅ Feature 2.1 — Longues reviews (inspiré Letterboxd)
**Ce que fait Letterboxd :** reviews riches, likées, commentées, avec spoiler tag
**Ce qu'on améliore :**
- **Richtext editor** : bold, italic, spoiler tag natif, lien vers un chapitre
- **Structure optionnelle** : l'utilisateur peut remplir des champs guidés (Histoire / Art / Personnages / Verdict) ou écrire librement
- **Review par arc narratif** (pas juste le manhwa entier — utile pour les séries longues)
- **"Évolution de ma note"** : si tu as noté 7/10 puis 9/10 en relecture → les deux s'affichent avec date

---

### ✅ Feature 2.2 — Micro-reviews (inspiré Twitter/Letterboxd)
**Innovation :** Séparées des longues reviews dans l'UI.
280 caractères max. Style "réaction immédiate après lecture".
Apparaissent dans le feed des abonnés. Plus virales, plus fréquentes.

---

### ✅ Feature 2.3 — Score séparé par dimension (inspiré CBR / IGN)
**Option pour les power users :**
En plus du score global /10, possibilité de noter séparément :
- 📖 Histoire
- 🎨 Artwork
- 👥 Personnages
- 🌍 Worldbuilding

Ces sous-scores sont optionnels. S'ils sont remplis → graphique radar sur la fiche.
**SEO bonus :** "Best manhwa for worldbuilding" devient une requête à laquelle on peut répondre avec des données.

---

### 🚀 Feature 2.4 — INNOVATION : "Review utile pour qui ?"
Chaque review peut être taguée par son auteur :
- "Pour les nouveaux lecteurs"
- "Pour ceux qui ont fini le tome X"
- "Review technique (artwork focus)"

L'utilisateur filtre les reviews selon son profil. Fini les reviews spoilers pour les nouveaux.

---

### 🚀 Feature 2.5 — INNOVATION : "Score Communauté vs Score Critique"
Inspiré de Rotten Tomatoes mais pour la communauté.
Afficher sur chaque fiche :
- **Score ManhwaVerse** : note agrégée de tous les membres (pondérée par le karma/influence du reviewer)
- **Score Critique Presse** : si des critiques professionnelles existent (en Phase 2, via agrégation manuelle)

La tension entre les deux scores est un contenu éditorial en soi : "Pourquoi la presse note X mais la communauté note Y ?"

## 🔍 CATÉGORIE 3 — DÉCOUVERTE

### ✅ Feature 3.1 — Tags de tropes communautaires (inspiré AniList)
**Ce que fait AniList :** tags genre votés par la communauté
**Ce qu'on améliore :**
- Tags spécifiques au manhwa : **#regression, #system, #op-mc, #murim, #villain-mc, #female-lead, #isekai-kr, #second-chance, #tower**
- Vote positif / négatif sur chaque tag (la communauté valide ou invalide)
- Tags affichés par ordre de votes (les plus représentatifs en premier)
- **Chaque tag = page SEO** avec tous les manhwas de ce tag

---

### ✅ Feature 3.2 — "Titres similaires" algorithmique (inspiré tout le monde mais jamais bien fait)
**La vraie innovation :** pas juste "même genre", mais similarité multi-dimensionnelle :
- Tropes en commun (pondération forte)
- Ambiance similaire (dark/light)
- Longueur comparable
- Score dans la même tranche
- "Les gens qui ont terminé X ont aussi terminé Y" (collaborative filtering pur, sans IA)

---

### ✅ Feature 3.3 — Listes communautaires (inspiré Letterboxd — sa feature signature)
**Ce que fait Letterboxd :** listes créées par les users, votées, ultra-populaires
**Ce qu'on améliore :**
- Listes avec **commentaire par item** ("Ce manhwa est dans cette liste parce que...")
- Listes **collaboratives** : plusieurs personnes peuvent contribuer
- Listes **versus** : "Manhwa À ou Manhwa B ?" — vote communautaire
- Top listes → **landing pages SEO automatiques** (la liste la plus populaire sur "manhwa like solo leveling" devient une page indexée)

---

### 🚀 Feature 3.4 — INNOVATION : Recherche par URL partageable
Chaque combinaison de filtres (trope + statut + note min + longueur) génère une URL unique.
Exemple : `manhwaverse.com/search?tropes=regression,system&status=completed&score=8`

**Pourquoi révolutionnaire :**
- Les gens partagent ces URLs sur Reddit, Discord, TikTok
- Chaque URL partagée = backlink potentiel + trafic direct
- Google indexe ces pages → SEO long-tail automatique

---

### 🚀 Feature 3.5 — INNOVATION : "Trending dans mon réseau"
Pas les trending globaux (déjà sur la home), mais **trending parmi les personnes que tu suis**.
"8 personnes que tu suis ont commencé [titre] cette semaine."
Crée un FOMO social naturel qui pousse à la découverte.

## 👥 CATÉGORIE 4 — SOCIAL & COMMUNAUTÉ

### ✅ Feature 4.1 — Follow & Activity Feed (inspiré Letterboxd)
**Ce que fait Letterboxd :** voir l'activité de ses abonnés en temps réel
**Ce qu'on améliore :**
- Feed chronologique ET feed algorithmique (choix utilisateur)
- **Filtrable** : "Montrer seulement les ✅ Terminé" / "Seulement les notes ≥ 8"
- **Réactions rapides** sur l'activité : 🔥 Hype / 👍 Noté / 💔 Sad

---

### ✅ Feature 4.2 — Profils publics riches (inspiré Letterboxd + MAL)
**Ce qu'on prend de MAL :** stats détaillées (genres, temps de lecture)
**Ce qu'on prend de Letterboxd :** design élégant, identité forte du lecteur
**Ce qu'on ajoute :** Taste Card partageable, Reader Class, heatmap de lecture

---

### 🚀 Feature 4.3 — INNOVATION : "Reading Rooms"
**Concept inédit :** Espaces de lecture synchronisée pour les groupes.
- Créer une "Room" autour d'un titre (privée ou publique)
- Les membres lisent ensemble (chacun à son rythme)
- Chat contextuel lié à un chapitre précis (zéro risque de spoiler)
- Réactions par chapitre (😱 💀 🔥 😭)
- À la fin : "Room Recap" avec les moments les plus réactés

**Cas d'usage :** book clubs manga, amis qui lisent ensemble à distance, event communautaire "Lisons Solo Leveling en 30 jours".

---

### 🚀 Feature 4.4 — INNOVATION : "Taste Match"
Deux utilisateurs peuvent voir leur **compatibilité de goûts** :
- % de titres en commun
- Titres où vos notes divergent le plus
- "Tu aimeras probablement X que ton ami a noté 9/10 et que tu n'as pas lu"

Viral entre amis. Crée du contenu partageable ("Ma compatibilité avec @ami est de 73% 😮").

---

### 🚀 Feature 4.5 — INNOVATION : "Spoiler-safe Discussion Threads"
Les discussions par chapitre existent sur Reddit de façon chaotique.
ManhwaVerse les structure :
- Thread de discussion par arc / saga
- Spoilers masqués automatiquement jusqu'au niveau de progression de l'utilisateur
- "Tu n'as pas encore lu le chapitre 80 — des spoilers sont cachés dans ce thread"
- L'utilisateur voit seulement les discussions jusqu'à là où il en est

**Techniquement :** chaque post est tagué avec le chapitre. Masquage conditionnel basé sur la progression enregistrée dans la bibliothèque.

### 🚀 Feature 7.4 — Reading Pace (personnalisation profonde)
**Concept :** Calculer le temps de lecture estimé d'un manhwa selon la vitesse de lecture personnelle de l'utilisateur.

```
Calibration (une fois, 2 minutes) :
"Lis ce chapitre test et dis-nous quand tu as fini"
→ On calcule : X minutes / chapitre = ta vitesse personnelle

Ensuite sur chaque fiche :
Solo Leveling — 179 chapitres
⏱️ Pour toi : environ 14h 20min de lecture
📅 À ton rythme (5 chap/jour) : fini en 36 jours
```

**Pourquoi c'est utile :** Les lecteurs veulent savoir si un manhwa de 300 chapitres vaut l'investissement. "Est-ce que j'ai le temps ?" est une vraie question avant de commencer.

## 🧊 CATÉGORIE 8 — COLD START STRATEGY

### Approche combinée (les trois en simultané)

**Pilier 1 — Beta testers pré-launch (200 reviews)**
Recruter 50 beta testers dans le Discord avant le lancement.
Chacun s'engage à rédiger 4 reviews minimum avant le lancement.
200 reviews sur les 50 titres les plus populaires = crédibilité immédiate.
Incentive : badge "Founding Member" permanent sur le profil.

**Pilier 2 — Fiches éditoriales SEO-first**
Les 500 titres importés d'AniList ont des synopsis complets, des tropes tagués, des liens de lecture.
Même sans une seule review, ces fiches sont des landing pages SEO valides.
Google indexe du contenu de qualité, pas des reviews.

**Pilier 3 — Import reviews MAL/AniList avec attribution**
Légalité : les reviews MAL/AniList sont sous licence Creative Commons dans certains cas.
Approche propre : afficher "Review importée depuis [source] · [Nom d'utilisateur sur source]"
avec lien vers l'original.
Cela donne du contenu visible ET transparent dès J1.
À terme, remplacées par les reviews natives ManhwaVerse.

**Séquence :**
```
J-60 : Recrutement beta testers Discord
J-30 : Beta testers rédigent leurs reviews
J-14 : Import AniList reviews avec attribution
J-7  : Vérification qualité + modération
J0   : Lancement avec 200+ reviews natives + 500+ reviews importées
```

## 🛡️ CATÉGORIE 10 — MODÉRATION AUTOMATIQUE

### Système de filtrage en couches

**Couche 1 — Liste de mots interdits (temps réel)**
```typescript
// /lib/moderation/wordlist.ts

const BLOCKED_WORDS = {
  fr: [/* liste FR : insultes, racisme, NSFW... */],
  en: [/* liste EN */],
  universal: [/* termes universels */]
}

// Regex avec variantes (l33tspeak, espaces, etc.)
// Ex: "f*ck", "f u c k", "f.u.c.k" → tous bloqués

export function containsBlockedContent(text: string, locale: string): boolean {
  const normalized = normalizeText(text) // lowercase, remove special chars
  return BLOCKED_WORDS[locale].some(word => normalized.includes(word))
    || BLOCKED_WORDS.universal.some(word => normalized.includes(word))
}

function normalizeText(text: string): string {
  return text
    .toLowerCase()
    .replace(/[^a-z0-9\s]/g, '') // retire les caractères spéciaux
    .replace(/\s+/g, ' ')         // normalise les espaces
}
```
